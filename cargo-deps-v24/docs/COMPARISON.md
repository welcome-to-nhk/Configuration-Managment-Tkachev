# Сверка с настоящим Cargo: этапы 4 и 5

## Статус

В среде подготовки Cargo не установлен, сетевой доступ Python к crates.io
не работал (ошибка DNS). Поэтому **реальные результаты cargo tree здесь
не получены**. В архиве нет выдуманного «успешного сравнения».
Автономные примеры и mock-тесты не заменяют эту часть требований.

## Как закончить сверку на своем компьютере

Установите Rust/Cargo с официального сайта https://rustup.rs/.
Проверьте `cargo --version`. Понадобится интернет.
Из корня проекта выполните:

```sh
python tools/compare_cargo.py --package crc32fast
python tools/compare_cargo.py --package miniz_oxide
python tools/compare_cargo.py --package itoa
```

Для каждого пакета появится папка `out/comparison/ИМЯ/`:
- Cargo.toml — отдельный проверочный проект с точной версией корня;
- cargo-tree.txt — настоящий текст штатной визуализации Cargo;
- comparison.json — различия вершин, ребер и проверка зависимостного порядка.

Инструмент вызывает **cargo tree --prefix depth --format {p} --no-dedupe
--edges normal,build --target all**. Это отдельная проверка, основной
анализатор не пользуется Cargo. Проверочный wrapper удаляется из сравнения.
Cargo.lock удаляется перед повтором, чтобы старый lock не фиксировал версии.
Корневая версия фиксируется на выбранной анализатором версии.

В comparison.json пустые списки *_only_* означают совпадение графов.
`order_violations=[]` означает, что среди общих ребер все зависимости
стоят до потребителей. При различающемся множестве вершин это **не**
доказательство полноты порядка для всего графа Cargo.

Для этапа 5 отдельно создайте онлайн-граф:

```sh
python -m src --package crc32fast --repository https://index.crates.io --output out/live-crc32fast.svg
python -m src --package miniz_oxide --repository https://index.crates.io --output out/live-miniz.svg
python -m src --package itoa --repository https://index.crates.io --output out/live-itoa.svg
```

Сопоставьте связи на SVG со строками cargo-tree.txt. Сохраните результаты
и сформулируйте фактические выводы. Не подменяйте их автономными снимками:
настоящий реестр со временем может выбрать другие версии.

## Как объяснять расхождения

1. **features / optional.** Cargo может активировать optional через default
   features; наш анализатор optional не включает вообще.
2. **Target.** Мы объединяем все target. Для близкого сравнения у cargo tree
   указан --target all; это все равно не заменяет полный resolver.
3. **Версии.** Мы выбираем максимум на каждом ребре независимо. Cargo
   может согласовывать версии между ветками и выполнять backtracking.
4. **MSRV и lock.** Cargo учитывает среду и lock; учебная модель — нет.
5. **Dev.** Они исключены у обоих, чтобы сравнивать библиотечные зависимости.
6. **Порядок.** cargo tree — дерево связей, не журнал сетевых скачиваний.
   Зависимостный порядок проверяется по ребрам; для независимых веток
   несколько последовательностей одинаково допустимы.

У Cargo есть штатная **текстовая** визуализация `cargo tree`.
Не нужно приписывать ему встроенную команду экспорта PlantUML/SVG.
Для защиты сравнивается содержание связей, не одинаковая раскладка картинки.
